Phase SR5.4 — Runtime Read Adapter Isolation

Root Cause:
Smart Reports still had mixed read ownership after canonical commit: smartData() read the legacy records array directly while runtime diagnostics could inspect other sources. There was no isolated read-only boundary over committed sales rows.

Fix:
Added an optional PETATOESmartReportsReadAdapter that snapshots canonical committed window.records rows only after petatoe:sales-records-committed. smartData() and the runtime controller now prefer the adapter while preserving legacy fallbacks. The adapter is not part of the critical Smart Reports startup gate and performs no fetching, commits, normalization, rendering, or Supabase access.
